# 文の見直し

書き終えた文書を、文の単位で見直すときに読む。意味・主張の強さ・範囲を変えずに直す。直すために元の資料にない事実を足さない。

## 一文一義と長さ

- 1 文には 1 つの内容だけを書く。「〜ので、〜が、〜し、」とつなげず、文を切る。
- 1 文は 60 字程度までを目安にする。
- 条件は指示の前に書く。条件に当てはまらない読者が、その指示を読み飛ばせるようにする。
  - 「`--force` を付けて再実行する。ただし、ロックファイルが残っている場合に限る。」は「ロックファイルが残っている場合は、`--force` を付けて再実行する。」と書く。
- 本則を先に書き、例外を後に書く。文を例外から始めない。

## 主語と動作主

- 誰が行うかを書く。人の操作は「〜する」と能動で書く。システムが起こすことは「〜される」と受け身でもよい。
- 責任の所在が問題になる文（仕様、障害報告）では、受け身でも主体を書く。
  - 「バックアップを取った上で消去される」は「夜間バッチがバックアップを取った後、データを消去する」と書く。
- 道具や概念を主語にして意志を持たせない。
  - 「この機能はデータ出力を可能にします」は「この機能を使うと、データを出力できます」と書く。
  - 「エラーが起動を妨げました」は「エラーのため、アプリケーションを起動できませんでした」と書く。
- 読者を「あなた」と呼ばない。

## 未定義語と曖昧な語

人によって受け取り方が変わる語は、具体的な内容に置き換える。資料から具体化できない場合は「未定」と書き、推測で埋めない。

| 語                                       | 具体的に書くこと                                     |
| ---------------------------------------- | ---------------------------------------------------- |
| 作成する、設定する、構築する             | どこで、何を使って、何を作るか。完了の判定           |
| 連絡する、共有する、報告する             | 誰に、どの手段（チャンネル名、宛先）で、何を伝えるか |
| 確認する、チェックする                   | 何を見て、どうなっていれば次へ進むか                 |
| 対応する、調整する、管理する、整備する   | 実際に行う操作                                       |
| 適宜、必要に応じて、場合によっては       | どの条件で行うか                                     |
| など、等                                 | 対象をすべて挙げる。挙げきれないなら代表例と範囲     |
| 基本的に、主に、原則として               | 例外は何か。例外がないなら語を削る                   |
| 十分な、大量の、一部の、すぐに、定期的に | 数値、期限、頻度                                     |

## 言い切りと確度

- 確かなことは言い切る。「〜と思われます」「〜かもしれません」「一概には言えませんが」でぼかさない。
- 確かでないことは確度を書く。「未確認」「推測（根拠: 同時刻のログに接続エラーが 120 件）」のように書く。
- 義務・禁止・推奨・可能を語で区別し、元の情報の強さを保つ。
  - 義務は「必ず〜する」、禁止は「〜しない」、推奨は「〜することを推奨する」、可能は「〜できる」と書く。
- 元の情報の範囲を保つ。「一部の環境で」を「常に」に変えない。根拠なく「必ず」「絶対に」「すべて」と書かない。

## 冗長な表現

| 書かない                   | 書く         |
| -------------------------- | ------------ |
| 実行することができる       | 実行できる   |
| 調査を行う、調査を実施する | 調査する     |
| 〜という形で設定する       | 〜に設定する |
| 〜することにより           | 〜すると     |
| 〜的な対応                 | 具体的な操作 |

「〜することができる」は、可能動詞にすると受け身・尊敬と紛れる場合（「食べられる」など）に限って残す。

## 肯定形で書く

- 否定の条件より、肯定の範囲を書く。「5 名以上は予約できません」は「予約は 4 名までです」と書く。
- 二重否定（「〜しないわけではない」）を使わない。

## 用語

- 1 つの概念を 1 つの語で呼ぶ。同じものを別の語で言い換えない。
- 読者が知らない用語と略語は、初めて使う箇所で定義する。
- 作業中や会話の中で生まれた呼び名（「さっきの方式」「案 B」）を、定義せずに使わない。
- 「これ」「それ」「上記」は、指す対象が 1 つに決まる場合だけ使う。迷う場合は名詞を繰り返す。
- 格助詞を省かない。「項目名変更します」ではなく「項目名を変更します」と書く。

## 修飾と読点

- 修飾する語を、修飾される語の近くに置く。長い修飾語を先に、短い修飾語を後に置く。
- 読点は、長い修飾語の境界と、語順を通常から入れ替えた箇所に打つ。1 文の読点は 3 個程度までにする。

## 文体と表記

- 1 つの文書の中で、敬体（です・ます）と常体（だ・である）を混ぜない。
- 見出しは体言止めか常体にし、句点を付けない。1 つの箇条書きの中では、文末と句点の有無をそろえる。
- 英数字の前後の空白、長音（「サーバー」か「サーバ」か）、全角・半角は、同じリポジトリや同じ場所の既存の文書に合わせる。既存の文書がなければ、1 つの文書の中で統一する。
- 識別子、コマンド、パス、製品名、エラーメッセージは原文の表記のまま書き、コードはバッククォートで囲む。

## 飾りと決まり文句

- 構成の予告（「本書では〜について説明します」「以下の 3 点を解説します」）を書かず、内容を直接書く。
- 締めの決まり文句（「まとめ」の繰り返し、「お役に立てば幸いです」）を書かない。
- 「簡単に」「単に」「〜するだけ」を書かない。つまずいた読者が、自分に問題があると考えてしまうため。
- 誇張する語（「非常に重要」「劇的に」「シームレスに」「最適な」）は、数値や事実に置き換える。
- 比喩（「羅針盤」「車の両輪」）、絵文字、感嘆符、ダッシュ（——）でつなぐ書き方を使わない。

## 英語で書く場合

- 命令形と能動態で書き、1 文に 1 つの内容を書く。
- "simply"、"just"、"easy"、"please note" を使わない。
- "currently"、"new"、"latest"、"soon" の代わりに、日付やバージョンを書く。
- 1 つの概念を 1 つの語で呼ぶ。
