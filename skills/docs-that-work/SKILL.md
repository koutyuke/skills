# Docs That Work

人間が読むことを前提に、必要最小限の情報で読者の理解を最大化する。対象読者が短時間で同じ全体像を持ち、必要な情報取得、判断、行動を迷わず完了できる文書にする。

## 進める

1. 文書種別、対象読者と前提知識、目的、読後に必要な情報、判断、行動を定める。仮定によって正確性、公開範囲、理解、行動、安全性が変わる場合だけユーザーへ確認する。
2. コード、設定、仕様、既存文書から、対象の環境、現在状態、版を確認する。正本が矛盾するか必要な事実を確認できない場合は、推測せず確認するか不明点として示す。事実、推論、提案、不明点を混同しない。
3. 読者に必要な現在の情報だけを選び、現在の方法と制約を直接書く。過去との比較、不採用・不要・中止・削除した内容、編集経緯、未決定の将来案は、それ自体が目的の履歴、計画、ADR、移行・互換性文書以外へ載せない。
4. 目的に合う構造を選ぶ。チュートリアルは学習順、手順書や Runbook は作業順、リファレンスは検索単位の事実、説明は背景と理由、設計文書や ADR は結論、根拠、制約、影響が追える順にする。
5. 最初の画面に、結論、全体像、読者の次の行動または必要な情報の探し方を置く。見出しだけでも主要な読み筋を追えるようにし、一つの段落では一つの論点を扱う。
6. 条件を指示より先に置き、各分岐を分岐元のスコープ内に置く。手順は番号付きの作業順とし、必要な実行場所、入力、期待結果、完了条件、失敗時の行き先を示す。副作用、機密情報、権限またはアクセスに関わる操作では、必要な実行主体、権限、対象、環境、影響、秘密情報の扱い、事前確認、停止条件、復旧またはエスカレーションも示す。
7. 安全な判断または実行に必要な情報源、判定基準、主体、権限、対象、方法、成功・失敗時の行き先が一つでも不明な文書は、文書の言語で該当経路が未完成かつ利用禁止であることを冒頭に明記し、不足情報と影響をまとめる。定義済みの部分だけを完成経路として扱わない。
8. 平易で一貫した用語を使い、必要な専門語は定義する。「定義する」「確認する」「対応する」「連絡する」「適切に」など、読者によって解釈が変わる語だけで済ませず、必要な主体、対象、手段、条件、完了状態を具体化する。元情報にない要素は作らない。
9. 関係、順序、境界、分岐への理解を速く正確にできる場合だけ、最小限の図やフローを全体像とともに最初の画面へ置く。読み進む方向を揃えて視線の往復を減らし、色、位置、線種や図だけに重要な意味を持たせない。
10. 削除しても理解、行動、安全性、認識の一致が損なわれない情報は書かない。変わりうる詳細は正本へ集約するが、読者が次の行動や参照先を選ぶための短い要約や条件は残す。

## 更新する

- 新規文書は既存の配置規則と読者の導線へ統合する。既存文書から将来案を除く場合は、既存の計画置き場へ移す。保管場所がなければ削除前にユーザーへ確認する。
- 更新では文書全体と、関連する識別子、コマンド、リンク、重複記述、生成元を確認する。生成物は直接編集せず、生成元を更新して再生成する。依頼対象外の正しい情報を保ち、元情報の義務、禁止、推奨、可能性の強さを変えずに現在の状態へ統合する。

## 確かめる

- 対象読者が最初の画面と見出しから目的、全体像、次の行動または必要な情報を選べるか確認する。
- 代表的な判断と全分岐を終端までたどり、前提、期待結果、完了条件、失敗時の行き先に抜けや矛盾がないか確認する。
- 重要、高リスク、または実行手順を含む文書では、利用可能なら文脈を持たない読者 Agent に文書と許可された参照先だけを渡し、目的、全体像、代表的な判断、次の行動を答えさせ、定めた目的や正本と一致しない箇所を修正する。利用できなければ未検証として報告し、公開・運用前の人間レビューを求める。
- 事実、リンク、パス、コマンド、コード例を正本と照合し、安全に実行できる検証は実行する。Markdown では見出し、リスト、表、リンク、コードフェンスの構造も確認する。
- これ以上削ると理解、行動、安全性、認識の一致のいずれかが損なわれる状態で完了し、未検証事項と残る不確実性を報告する。
