# Docs That Work

後から読む人が、短時間で同じ全体像を持ち、必要な判断・行動を完了できる文書にする。文書の価値は、読者の探す手間と解釈の余地をどれだけ減らせるかで決まる。

## 残す情報を選ぶ

- 依頼と既存文書から、読者の前提知識と読後に必要な判断・行動を定める。「この情報がなければ読者は何を誤解し、判断できず、実行できなくなるか」で残す情報を選ぶ。必要な背景、具体例、判断理由、制約は残す。
- 現在の仕組み、方法、条件を直接書く。会話への返答、試行錯誤、訂正履歴を本文へ持ち込まない。否定や比較は、選択・互換性・安全性・結果の解釈に役立つ場合だけ使う。ADRやPRに必要な変更前後と判断理由は残す。
- 検証結果と未確認事項は、読者の利用条件や判断に影響するものを本文へ、今回の作業報告だけに必要なものを完了報告へ置く。

## 読者が使う順に組む

- 冒頭に結論と全体像、次の行動または情報の探し方を置く。図が関係・順序・境界を文章より速く伝えるなら、最小限の図を添える。図の読み進む方向を揃え、色や図だけに意味を持たせない。
- 資料の記載順を引き継がず、読者が判断する順に並べ直す。手順は「前提・対象・注意 → 操作 → 期待結果と次の行動」のまとまりにする。読者は先を読まずに操作するため、共通の注意は最初の該当操作より前に置く。
- 「確認する」「対応する」「連絡する」だけで済ませず、必要な主体・対象・手段・判定基準を示す。実行場所と入力、完了条件、失敗時の行き先を、資料で確認できる範囲で具体化する。読者が知らない用語は定義する。
- 分岐先の作業は分岐元の配下へまとめる。詳細を正本へ集約するときも、移動する条件と必要な要約を残す。見出しで読み筋を示し、一段落は一論点にする。

## 正本と読者の行動で確かめる

- コード、設定、仕様など、記述の正本と照合する。版や環境を区別し、元情報の義務・禁止・推奨・可能性の強さを保つ。未定の担当や手続を慣例で埋めず、未検証を機能上の制約や禁止へ読み替えない。
- データや外部状態を変えるなどの手順で、安全な判断に必要な情報が欠けた経路には不足と影響を示し、完成した実行手順として提示しない。確定済みの調査・説明は進める。解消できない曖昧さが重要な要件・公開範囲・安全性を分ける場合だけ確認する。
- 更新と検証は依頼範囲と影響先に絞る。対象外の正しい情報や計画を保ち、生成物は生成元を直す。変更した事実・リンク・コマンドを照合し、安全に行える確認を実行する。
- 冒頭から読者の行動をたどり、操作の直前までに必要な条件・注意が揃うか、各分岐から完了・引き継ぎへ進めるかを確かめる。判断が分かれやすい文書は必要に応じて会話履歴を持たない読者Agentで確かめる。依頼範囲の修正と必要な照合が終われば完了する。
